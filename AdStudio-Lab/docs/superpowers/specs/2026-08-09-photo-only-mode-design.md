# 사진만으로 광고 영상 만들기 (사진 모드) — 설계

작성일: 2026-08-09
대상: `D:\AdStudio-Lab`
상태: 승인됨 (구현 계획 대기)

## 1. 배경과 목적

지금 AdStudio 는 제품 URL·설명서·텍스트를 Gemini 가 분석해 컨셉을 만들고,
**화면에 나오는 그림은 전부 AI 가 새로 생성한다.** 그래서 화장품 튜브를 찍어 올려도
영상에는 다르게 생긴 튜브가 나온다. 광고주가 자기 제품을 못 알아본다.

이 설계는 **사진만 첨부해도 그 사진이 씬 화면이 되어 영상이 만들어지는 모드**를 추가한다.
기존 모드는 그대로 남는다.

효과는 두 가지다.

- **정확성** — AI 가 상상한 제품이 아니라 실제 제품이 화면에 나온다.
- **비용** — AI 이미지 생성이 0회가 된다. 이 프로젝트 비용의 대부분이 Gemini 이미지 생성이었다.

## 2. 이미 있는 것 — 이 기능의 뼈대

새로 만들 게 적다. 배관이 대부분 깔려 있다.

## 3. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 사진의 역할 | **분석 소스 + 씬 화면 둘 다** | 사진만 넣으면 분석부터 화면까지 해결된다 |
| 씬 개수 | **사진 장수 = 씬 개수** | 사용자가 정한 규칙 |
| 영상 길이 | **사진 장수가 결정한다** (사용자가 고르지 않는다) | 길이를 따로 고르면 사진 수와 충돌한다 |
| 길이 조절 수단 | **템포 3단계** (빠르게 2초 / 보통 3초 / 여유있게 4초) | 씬 길이가 코드상 2~4초로 묶여 있어 그 안에서만 조절 가능 |
| 모션 방식 | **켄번스(무료) 기본**, 유료 어댑터는 선택 | 제품 사진은 정지 컷이라 켄번스로 충분하다. 사진 10장 기준 유료는 $3~4, 무료는 0원 |
| 최소 장수 | **3장** | 코드상 씬 최소가 3개(`MIN_SCENES`). 2장 6초는 광고로 못 쓴다 |
| 분석에 쓸 장수 | **앞 3장만** | 전부 보내면 Vision 비용이 장수만큼 는다 |

### 길이 계산

```
영상 길이 = 사진 장수 × 템포
```

| 사진 | 빠르게(2초) | 보통(3초) | 여유있게(4초) |
|---|---|---|---|
| 3장 | 6초 | 9초 | 12초 |
| 5장 | 10초 | 15초 | 20초 |
| 7장 | 14초 | **21초** | 28초 |
| 10장 | 20초 | 30초 | 40초 |
| 20장 | 40초 | 60초 | 80초 |

**21초 같은 비표준 길이를 그대로 둔다.** 이 앱의 광고가 나가는 곳이 밴드·페이스북·스레드
같은 SNS 라 길이 규격이 없다. 30초에 억지로 맞추려면 없는 씬을 지어내야 하는데,
그건 "사진 수가 길이를 정한다"는 규칙을 스스로 어기는 것이다.

## 4. 흐름

```
A2 자료 업로드
 └ [사진] 탭 (신규) — 여러 장 첨부
     → 앞 3장을 Gemini Vision 에 넘겨 제품 분석 → AdAnalysis
     → 사진 N장 저장 (Photo[], faces 는 빈 배열)

A3 영상 설정
 └ 사진 모드면 길이 선택(15/30/60) 자리에 템포 3단계
     하단에 "사진 7장 · 약 21초" 표시

A4 배우 ─── 사진 모드는 건너뛴다 (§5 참조)

A5 컨셉 → A6 스토리보드
 └ 씬 개수 = 사진 장수
     씬 i 의 keyframeUrl ← 사진 i 의 previewUrl

A8 제작
 └ ensureKeyframe 이 사진을 그대로 반환 → AI 이미지 생성 0회
     기본: ffmpeg 켄번스로 클립 생성 (무료)
     선택: 유료 어댑터에 사진을 첫 프레임으로 전달
```

## 5. A4 배우 단계를 건너뛰는 이유

사진 모드에서는 **모든 씬이 사진으로 채워진다.** AI 가 그리는 화면이 하나도 없으므로
AI 가상 배우도, 업로드한 배우 사진도 렌더될 자리가 없다. 단계를 남겨두면 사용자가
설정한 배우가 결과에 전혀 반영되지 않아 "왜 내가 고른 배우가 안 나오지"가 된다.

`A4_Actor.tsx:29` 의 분기(`navigate(mode === 'photo' ? '/upload' : '/concept')`)를 타지 않고
A2 → A3 → A5 로 직행한다.

**하류 영향 없음**을 확인했다 — `generateStoryboardScenes(project, persons)` 에
`persons=[]` 가 들어가면 `hasModel: false` 가 되어 프롬프트 문구만 달라진다.
나레이션 목소리는 `config.voice` 에서 오므로 배우와 무관하다.

## 5-1. 씬 개수 강제와 씬 텍스트 — 오마주 때와 같은 함정이 있다

`generateStoryboardScenes` 는 씬 개수를 두 단계로 정한다:

```ts
const desiredCount = Math.max(3, Math.round(durationSec / SCENE_SEC_TARGET))
const sceneCount = Math.min(desiredCount, pool.length)   // ← 풀 크기로 잘린다
const chosen = pool.slice(0, sceneCount)
```

**사진 모드는 이 계산을 타면 안 된다.** 사진 10장인데 `AD_CONCEPT_TEMPLATES` 의 풀이
6개면 `Math.min` 이 6으로 잘라, 사진 4장이 버려지고 길이도 어긋난다.
사진 모드는 `sceneCount = photos.length` 를 그대로 쓴다.

그런데 여기서 오마주 모드와 **똑같은 함정**이 따라온다. 풀보다 씬이 많으면 텍스트를
어디서 가져오느냐는 문제다. 오마주 구현에서 `pool[i % pool.length]` 로 순환시켰다가,
Gemini 실패 시 `DEFAULT_CONCEPT_TEMPLATE` 의 로맨틱 대사("기억해줘, 우리의 시간.")가
제품 광고의 최종 결과로 나가는 Critical 을 만들었다. 같은 실수를 반복하지 않는다.

**규칙:**

- 씬 대사·설명은 **Gemini 광고 각본 생성이 `sceneCount` 개를 만든다.**
  `AdAnalysis`(사진 분석 결과) + A5 에서 고른 컨셉이 입력이다.
- 폴백 초기값은 템플릿 풀에서 **가져오지 않는다.** `dialogueKo: ''` 로 두어,
  만에 하나 흘러가도 기존 "대사 보증" 안전망이 발동하게 한다.
- **Gemini 각본 생성이 실패하면 사진 모드는 명시적으로 실패한다.**
  조용히 템플릿 텍스트로 대체하지 않는다. 사용자가 사진을 올려 만든 광고에
  무관한 문구가 들어가는 것보다, 실패를 알리고 다시 시도하게 하는 편이 낫다.

`keyframePromptEn` 은 사진 모드에서 **쓰이지 않는다** — `ensureKeyframe` 이
`keyframeUrl` 을 보고 조기 반환하므로 이미지 생성 프롬프트가 소비되는 지점이 없다.

**A5 컨셉 단계는 그대로 남는다.** 카테고리·강조점·톤이 광고 각본 생성의 입력이라
사진 모드에서도 필요하다. 다만 스토리 구성(`structureId`)은 씬 개수를 정하는 데
쓰이지 않는다(사진 장수가 정한다) — 각본의 서사 방향에만 반영된다.

## 6. 데이터 모델

`AdConfig` 에 세 필드를 추가한다.

```ts
photoMode: boolean        // 기본 false — 기존 동작 보존
tempo: 2 | 3 | 4          // 씬당 초. 기본 3
duration: number          // 15|30|60 유니온 → number 로 완화
```

**`duration` 타입 완화가 필요한 이유:** 7장 × 3초 = 21초처럼 세 값 밖의 길이가 나온다.
`Project.durationSec` 은 이미 `number` 라 하류는 손댈 게 없다.
`A3_AdConcept.tsx:10` 의 `DURATIONS = [15, 30, 60]` 은 기존 모드 UI 선택지라 그대로 둔다.

**사진은 localStorage 에 저장하지 않는다.** `adStore` 의 `partialize` 가 이미
`actorPhotoDataUrl` 을 제외하는 것과 같은 이유다 — 사진 10장이면 base64 로 10MB 가 넘어
localStorage 한도를 넘긴다. 사진은 메모리(`projectStore.photos`)와 Firestore
서브컬렉션에만 둔다.

## 7. 통합 지점

| 지점 | 처리 |
|---|---|
| 얼굴 검출 | `Photo.faces` 는 오마주 앱의 인물 추출용이다. 제품 사진에 돌리면 시간만 쓰고 빈 배열이 나온다. 사진 모드는 `faces: []` 로 건너뛴다 |
| 비율 정규화 | 켄번스 함수가 `targetW x targetH` 로 크롭해 출력이 통일된다. 다만 세로·가로 사진이 섞이면 크롭이 심하게 잘리므로, 업로드 시 잘릴 영역을 미리보기로 보여준다 |
| 사진 순서 | 업로드 순서가 곧 씬 순서다. A6 스토리보드에 이미 순서 편집(`@dnd-kit`)이 있어 거기서 바꾼다 |
| 업로드 리사이즈 | 긴 변 1920px 로 줄여 보관한다. 원본을 그대로 들고 있으면 ffmpeg.wasm 메모리가 터진다 |

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 사진 3장 미만 | 진행 차단 — "최소 3장이 필요해요" |
| 분석 실패 | 사진은 남기고 컨셉을 수동 입력하도록 유도한다. 사진이 이미 있으니 영상은 만들 수 있다 |
| 켄번스 실패 | 해당 씬만 정지 화면으로 폴백하고 **알린다**. 조용히 넘어가지 않는다 |
| 사진이 너무 큼 | 업로드 시 리사이즈로 처리 (§7) |

## 9. 검증

**회귀가 최우선이다.** `photoMode: false` 일 때 다음이 도입 전과 완전히 같아야 한다 —
A2 의 기존 3탭, A3 의 15/30/60 선택, A4 배우 단계, AI 키프레임 생성.

| 종류 | 내용 |
|---|---|
| 회귀 | `photoMode: false` 경로 전체. `duration` 타입 완화가 기존 15/30/60 선택을 깨지 않는지 |
| 유닛 | 길이 계산(장수 × 템포), 최소 장수 검증, 사진→씬 배정 |
| 통합 | `keyframeUrl` 이 채워진 씬에서 AI 이미지 생성이 **0회** 호출되는지 |
| E2E | 3·5·7·10·20장으로 각각 영상 생성. 비율 다른 사진이 섞여도 최종 해상도가 일정한지 |

## 10. 위험과 미결

| 항목 | 내용 |
|---|---|
| ffmpeg.wasm 메모리 | 사진 20장 × 60초를 브라우저에서 렌더하는 부하가 미검증이다. 장수 상한이 필요할 수 있다 |
| 켄번스 단조로움 | 모든 씬이 같은 방향으로 확대되면 지루하다. 씬마다 방향(확대/축소/좌우 팬)을 바꾸는 것이 개선 여지 |
| 오마주 모드와의 조합 | 사진 모드 + 유튜브 오마주를 같이 고르면 씬 개수가 충돌한다(사진 장수 vs 레퍼런스 구조). 초기 구현에서는 **둘 중 하나만** 고르게 막는다 |
