# 보랏빛 소 실행 체크리스트 (운영자용)

세스 고딘 《보랏빛 소가 온다》의 **실행 지침 8가지**를 AutoAd 운영에 대입한 문서다.

이 문서가 따로 있는 이유는 하나다.

> **"제품을 만든 뒤에 광고 문구를 고민하는 것이 아니라,
> 제품 기획 단계에서부터 리마커블함을 빌트인하는 것"**

이 말이 맞다면, 8지침 중 상당수는 **문구 생성기에 넣으면 안 된다.**
LLM 은 광고 문구를 쓰는 중에 제품을 바꿀 수 없다. 못 하는 일을 시키면
LLM 은 거절하지 않고 **지어낸다** — 없는 기능을 있는 것처럼 쓴다.
그건 리마커블이 아니라 표시광고법 위반이다.

그래서 8지침을 둘로 갈랐다.

---

## 1. 8지침 판정 — 무엇을 엔진에 넣었고 무엇을 여기 남겼는가

| # | 지침 | 판정 | 지금 어디에 있는가 |
|---|------|------|-------------------|
| 1 | 제품 변화 (10가지) | **사업 결정** | 이 문서 §2-1 |
| 2 | 초소형 시장 타깃 | **카피 레버** | `content/prompts/_purplecow.txt` A절 — 전 업종·전 채널 적용 |
| 3 | 아웃소싱 | **사업 결정** | 이 문서 §2-2 |
| 4 | 허락자산 구축 | **부분 (CTA만)** | `content/prompts/_permission.txt` — **콘텐츠형 글에만** |
| 5 | 타 산업 모방 | **사업 결정** (문구 단계는 위험) | 이 문서 §2-3 |
| 6 | 정반대로 실행 | **카피 레버 (울타리 필수)** | `_purplecow.txt` B절 |
| 7 | 업계 최초 시도 | **사업 결정 + 문구 단계는 역방향 금지** | 이 문서 §2-4 / 금지는 `_purplecow.txt` 레일 2번 |
| 8 | 근본적인 의문 | **사업 결정 + 안전한 변형만 문구화** | 이 문서 §2-5 / 변형은 `_purplecow.txt` C절 |

### 왜 1·3·5·7·8을 문구 생성기에서 뺐는가

- **1 (제품 변화)** — LLM 이 제품을 바꿀 수 없다. "제품을 근본적으로 바꿔라"를
  문구 지시로 번역하면 결과는 "없는 기능을 있는 것처럼 쓰기"다.
- **3 (아웃소싱)** — 문구와 아무 관계가 없다.
- **5 (타 산업 모방)** — "다른 산업의 리마커블을 베껴라"는 LLM 에게 **형식 폭주**
  지시다. 뉴스속보체·당첨안내체·공문체로 간다. 공적기관을 흉내 낸 광고는
  기만적 표시(표시광고법 제3조)이고, 대출 업종에서는 금융기관 오인
  (금융소비자보호법 제22조)까지 얹힌다.
- **7 (업계 최초)** — "최초·유일·1위"는 그 자체가 **실증책임 대상**
  (표시광고법 제5조)이다. 아래 §3 대로 지금 14개 업종 중 11개는 실증자료가 0이다.
  넣지 않는 데 그치지 않고 **명시적으로 금지**했다(프롬프트 레일 + 코드 검사).
- **8 (근본적 의문)** — "왜 안 되는데?"를 LLM 이 문구로 번역하면 정확히
  **"다들 안 된다지만 우리는 됩니다"** 가 나온다. 2026-08-10 에 위법 판정으로
  제외된 문구와 같은 형태다. 관행을 **부정**하지 말고 **설명**하는 쪽
  (`_purplecow.txt` C절)만 문구화했다.

## 2. 운영자가 직접 해야 하는 것

각 항목은 "지금 답할 수 있으면 답을 채우고, 모르면 물음표로 남겨 두는" 형태다.
**모르는 것을 지어내 채우면 그 순간 이 문서가 위험해진다.** 채워진 답은 결국
`profiles/*.yaml` 의 `facts` 로 들어가고, `facts` 에 있는 값만 광고 문구에 쓸 수 있다.

### 2-1. 제품 변화 — "고객의 호감을 살 수 있도록 근본적으로 바꿀 10가지"

업종 하나를 골라, 그 업종의 결과물이 **어디서 실망을 주는지**부터 적는다.
리마커블은 새 기능이 아니라 **실망 지점의 제거**에서 더 자주 나온다.

- 지금 이 서비스를 쓴 사람이 가장 자주 하는 불평은 무엇인가?  → (   )
- 결과물을 받은 뒤 사람들이 **직접 손보는 부분**은 어디인가?  → (   )
  (그걸 대신 해 주는 것이 대개 가장 싼 리마커블이다)
- 경쟁 서비스가 **당연히 준다고 여기는 것** 중 우리가 안 주는 것은?  → (   )
- 반대로 우리만 주는데 **아무도 모르는 것**은?  → (   )
  → 이건 제품 변화가 아니라 **문구 문제**다. 알아냈으면 `facts` 에 등록하라.
- 결과물을 받는 데 실제로 걸리는 시간은?  → §3 참조. 측정값이 없으면 측정부터.

⚠ 이 칸을 채운 뒤 **반드시** 확인할 것: 바꾸기로 한 것이 광고에 나갈 주장이라면,
그 주장을 뒷받침할 근거가 있어야 한다. 근거 없이 광고에 실으면 위법이다.

### 2-2. 아웃소싱 — "핵심 역량에 집중하고 나머지는"

AutoAd 관점에서 이미 아웃소싱된 것과 아직 손으로 하는 것을 갈라 본다.

- 이미 자동화된 것: 소재 생성 · 캡션 생성 · 채널 발행 · 승인 큐
- 아직 사람이 하는 것: 승인 판단, `facts` 등록, 업종 프로필 작성,
  채널 발굴/분류 검수
- 질문: 위 넷 중 **품질이 곧 매출인 것**은 무엇인가?  → (   )
  그것만 남기고 나머지를 줄이는 것이 이 지침의 실행이다.
- 질문: 승인 판단을 하루 몇 건 하고 있고, 그중 실제로 손대는 비율은?  → (   )
  (손대는 비율이 낮으면 승인은 병목일 뿐 품질장치가 아니다)

### 2-3. 타 산업 모방 — "전혀 다른 산업의 리마커블한 아이디어"

⚠ **문구 형식을 베끼지 마라.** 베낄 것은 형식이 아니라 **구조**다.

- 다른 산업에서 "결과를 먼저 보여주고 나중에 받는" 방식은 무엇이 있는가?  → (   )
- 우리 업종에서 고객이 **사기 전에 결과를 볼 수 있는가**?  → (   )
  (미리집·프리뷰 계열은 이미 이 구조다. 나머지 업종은?)
- 다른 산업에서 "실패하면 돈을 안 받는" 방식을 우리에 대입하면?  → (   )

⚠ 대출 업종에는 이 지침을 적용하지 마라. 금융은 형식 자체가 규제 대상이라
"다른 산업처럼 보이게" 만드는 시도가 곧 오인 유발이 된다.

### 2-4. 업계 최초 — "이 산업에서 아직 행해지지 않은 것"

먼저 하는 것은 좋다. **먼저 했다고 광고에 쓰는 것**이 위험하다.

- 우리 업종에서 아무도 안 하는 것 중, 우리가 할 수 있는 것은?  → (   )
- 그것을 **했다는 사실을 어떻게 증명**할 수 있는가?  → (   )
  증명할 수 없으면 광고에 '최초'라고 쓰지 마라. **한 일 자체를 설명**하면 된다.
  ("업계 최초 비대면 상담" ❌ → "상담부터 서류까지 만나지 않고 진행합니다" ⭕)

### 2-5. 근본적 의문 — "왜 안 되는데?"

이 질문은 **사업에는 던지고 광고에는 던지지 마라.**

- 우리가 "원래 이렇게 하는 것"이라고 믿고 있는 절차는?  → (   )
- 그중 고객이 **불편해하지만 우리 편의를 위해 유지**되는 것은?  → (   )
- 그걸 없애면 무엇이 깨지는가?  → (   )

⚠ 답이 "규제 때문에 그렇다"라면 그것은 뒤집을 대상이 아니다.
`_purplecow.txt` B절이 조건·심사·자격·요금·법정 표기를 뒤집기 금지로 못 박은 이유다.

## 3. 지금 당장 가장 큰 병목 — `facts` 가 비어 있다

지침 1(제품 변화)의 **실질적인 첫 항목**은 이것이다.

문구 생성기는 시간·횟수·배수·퍼센트를 **`profiles/*.yaml` 의 `facts` 에 있는
값만** 통과시킨다(`content/copy_engine._find_unverified_numbers`).
근거 없는 성능 수치는 표시광고법 위반이라 잘라낼 수도 없고 폴백으로 보낸다.

2026-08-10 현재 상태:

| `facts` 있음 (3) | `facts` 비어 있음 (11) |
|---|---|
| adstudio — 영상 생성 1~3분 | colorcraft, homage, loan, memoryfilm, mirizip, |
| inkcraft — 도안 생성 30초~1분 | nailpreview, petportrait, photomagic, proheadshot, |
| printcraft — 도안 30초~1분 / 배송 3~7일 | stickerme, wallpreview |

**결과**: 11개 업종은 `[수치 금지]` 분기를 탄다. 그런데 프롬프트는 동시에
"구체적으로 써라"라고 요구한다. 구체성을 요구받고 쓸 숫자가 없으면 LLM 은
숫자를 지어낸다 — 2026-08-09 사고("40초 만에", "1분 만에")가 정확히 이 패턴이다.

**할 일**: 업종마다 아래 한 줄씩만 **실제로 재서** 채운다.

- 결과물이 나오기까지 실제로 걸리는 시간 (범위로 적어도 된다. 범위가 더 정직하다)
- 한 번에 받는 결과물 개수
- 배송·전달이 있다면 그 소요일

⚠ 범위로 적으면 **범위째로만** 쓸 수 있다. `30초~1분` 을 등록해 두고 문구에
`30초 만에` 라고 쓰면 차단된다(가장 빠른 경우만 내세우는 것이라 실증 범위 밖이다).

⚠ 대출(loan)에는 성능 수치를 넣지 마라. 처리 속도·승인 관련 수치는 그 자체가
승인 암시로 읽힌다.

## 4. 규제 업종에서 리마커블을 요구할 때의 원칙

2026-08-10, 운영자가 확보한 광고 이미지 중 아래가 **위법 판정돼 제외**됐다.

- ★5 고객 후기 4건 + "40대 직장인 김OO님" → 허위 후기
- "신용평점 나빠도 상관無", "연체자 도 가능함", "조회기록 無 & 대출기록 無"
  → 확정·과장 표현

**이것들은 정확히 '눈에 띄는' 카피다. 그리고 불법이다.**
리마커블을 세게 요구할수록 이 방향으로 간다. 그래서 요구와 함께 레일을 깔았다.

원칙 한 줄로 줄이면:

> **리마커블함은 '검증 가능한 구체성'에서만 나온다.**
> 후기·평점·승인률·심사 완화는 리마커블이 아니라 위법이다.

자가 진단 2번("이게 뭐야? 하고 멈추게")을 규제 업종에서 푸는 방법은
**표현의 참신함** 하나뿐이다. **조건의 파격**으로 풀면 그건 광고가 아니라 위반이다.

### 지금 걸려 있는 자동 방어 (참고)

| 층 | 무엇을 막는가 | 어디 |
|---|---|---|
| 프롬프트 레일 (전 업종) | 지어낸 후기·순위 주장·부당비교·지어낸 사실 | `content/prompts/_purplecow.txt` 맨 끝 |
| 프롬프트 레일 (규제 업종) | 결과 단정·절차 부정·처지 지칭·'최초/유일/1위'·수치 | `content/prompts/_compliance_rail.txt` |
| 각도 제외 | '후기처럼 / 전후 대비 / 실패 먼저' 각도를 loan 에 배정하지 않음 | `profiles/loan.yaml` 의 `copy.deny_angles` |
| 코드 검사 (전 업종) | 별점·평점·"OO님"·제3자 인용·순위 주장·부당비교 | `_find_fake_testimonial` / `_find_superlatives` / `_find_unfair_comparison` |
| 코드 검사 (규제 업종) | 연체·신용·거절·무심사·절차 부정·승인 보장·결과 예단·처지 좁히기·1인칭 체험담 | `_find_approval_claims` |
| 코드 검사 (기존) | 금칙어 · 지어낸 수치(한글 수사 포함) · 낯선 문자 · 타사 홍보 | `copy_engine` |
| 조각 존재 확인 | 위 프롬프트 조각이 사라지면 카피 생성이 예외로 막힌다 | `_REQUIRED_SHARED` / `preflight.prompt_fragment_gaps()` |

⚠ **규제 레일은 규제 업종에만 붙는다.** 전 업종에 붙이면 심사가 존재하지도
않는 업종에 "심사를 뒤집지 마라", "가능합니다 를 쓰지 마라"라고 말하게 된다.
mirizip 의 "주말에도 상담 가능합니다" 는 완전히 적법하다.

⚠ **승인 콘솔 '수정' 경로도 같은 기준을 진다**(`copy_engine.regenerate`).
예전에는 이 경로만 방어가 1/4 이었다 — 금칙어를 문자열로 잘라내 저장하고
(`'누구나 가능한 상담' → '한 상담'`), 타사 주소 검사가 아예 없었다.

⚠ **사람 검수는 이 목록에 없다.** `tools/auto_loop.py` 가 20분 주기로 자동
발행하므로, 위 층들이 현재로선 유일한 방어선이다. 새 업종을 규제 업종으로
편입할 때는 `profiles/<key>.yaml` 에 `compliance.mandatory_required` 를
선언해야 승인·심사 검사와 규제 레일이 함께 켜진다(선언이 곧 스위치다).

## 5. 이 문서를 다시 볼 때

- `_purplecow.txt` 를 고칠 때 — 14업종 × 4프롬프트 **전부**에 걸린다.
  `tests/test_purplecow.py` 를 먼저 돌려라.
- 새 업종을 추가할 때 — §2 를 그 업종에 대해 한 번 채우고, §3 의 `facts` 를
  측정해 등록하라. 둘 다 안 하면 그 업종의 카피는 "무난하거나, 위법하거나"
  둘 중 하나가 된다.
